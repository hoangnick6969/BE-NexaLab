- (direction) Parent asked for TAI-04 spec: extend B2 deterministic support signals with versioned rule-based insights; no LLM in v1, no ranking, no cheating/true-ability labels, teacher-only, never changes score or progress.
- (note) Brownfield: B2 flags are pure supportFlags() in src/modules/reports/application/evidence-support.ts (OVERDUE_INCOMPLETE, QUIZ_FAILED_TWICE, PRACTICAL_NOT_PASSED, NO_ACTIVITY_7_DAYS) served by GET classes/:classId/assignments/:assignmentId/support; computed on read.
- (note) Brownfield: evidence sources are QuizAttempt (score, passed, assignmentId), AssignmentSubmission (score, timing, LateDecision), Attempt (verdict, assignmentId, lessonStepId) with HintLog levels 1-4, Lesson.outcomeCodes; labs/tutor.ts misconceptions() needs 3 recent attempts.
- (note) Brownfield: no student free-text explanation exists on quiz or practical attempts, so explanation-mismatch rules need TAI-02 constructed responses.
- (capability) CAP-1 class insight overview for the owning teacher; success: every insight shows rule code, ruleVersion, status, neutral message and evidence IDs that drill to B2 evidence detail.
- (capability) CAP-2 first-wave rules INSUFFICIENT_EVIDENCE, SCORE_CHANGE_UNUSUAL, HIGH_HINT_DEPENDENCE, OBJECTIVE_MASTERY_INCONSISTENT with exact thresholds; success: boundary fixtures decide each rule.
- (capability) CAP-3 teacher acknowledge or dismiss an insight with note; success: append-only record keyed by fingerprint, insight hidden from open list but replayable.
- (capability) CAP-4 replay: any insight can be recomputed for a past instant with its ruleVersion; success: replay of a stored fingerprint reproduces identical evidence IDs.
- (capability) CAP-5 second-wave rules MCQ_EXPLANATION_MISMATCH and SIMULATION_EXPLANATION_MISMATCH after TAI-02, SUBMISSION_SIMILARITY_HIGH after TAI-03; success: they consume only teacher-final grades or deterministic similarity output, never AI suggestions.
- (decision) Insights are computed on read by pure versioned functions (ruleVersion insights@1) over immutable evidence; no insight table; only acknowledgements persist.
- (decision) Scope is one class: evidence whose assignmentId belongs to the class and student currently approved; free practice and removed students excluded, matching B2.
- (decision) Qualifying scored attempt: QuizAttempt with class assignmentId, or AssignmentSubmission excluding LATE pending and REJECT_ZERO; practical Attempt counts for hint and mastery rules.
- (decision) INSUFFICIENT_EVIDENCE when fewer than 3 qualifying scored attempts; then no score-based insight is emitted for that student.
- (decision) SCORE_CHANGE_UNUSUAL: baseline = up to 10 previous scored attempts (min 3), flag when abs(latest - mean) >= max(2 * population sd, 25 points); both directions; neutral wording.
- (decision) HIGH_HINT_DEPENDENCE: >=3 practical attempts in scope and 3 * count(max hint level >= 3) >= 2 * total; pattern SUDDEN_UNAIDED_PASS when the 3 previous attempts each used level >= 3 and the latest passed with no hint.
- (decision) OBJECTIVE_MASTERY_INCONSISTENT: for one outcome code, >=1 passing evidence of one type and >=2 non-passing of another type among >=3 evidence items linked through Lesson.outcomeCodes.
- (decision) Statuses: NEEDS_MORE_EVIDENCE for INSUFFICIENT_EVIDENCE, INFORMATIONAL for HIGH_HINT_DEPENDENCE base and OBJECTIVE_MASTERY_INCONSISTENT, TEACHER_REVIEW_RECOMMENDED for SCORE_CHANGE_UNUSUAL, SUDDEN_UNAIDED_PASS and second-wave rules.
- (decision) Fingerprint = sha256(ruleVersion, ruleCode, classId, studentId, sorted evidenceIds); new evidence produces a new fingerprint so a dismissal never hides new evidence.
- (decision) Lists are ordered by student display name then rule code; no severity score, count ranking or sorting by insight volume.
- (constraint) Never visible to students, parents or outsider teachers; never included in parent reports or exports; never changes score, verdict, progress, gates or overrides.
- (constraint) No LLM or provider call in this spec; any future model runs in shadow mode only under a separate spec.
- (question) Should SUDDEN_UNAIDED_PASS be shown at all in pilot, given it can read as suspicion of the student?
- (question) Is the 25-point floor and 2-sd rule acceptable to the product owner for SCORE_CHANGE_UNUSUAL?
- (decision) Tickets TAI4-T1..T7; T5 waits for TAI-02, T6 waits for TAI-03 submission similarity.
- (decision) Second-wave rules ship as insights@2 so insights@1 fingerprints stay replayable; thresholds for insights@2 are fixed in insight-rules.md before TAI4-T5.
- (decision) SPEC status draft-blocked-on-po-threshold-approval; TAI-04 needs no provider and no TAI-01 runtime.
