- (direction) User asked to define the Teacher AI idea (generation, duplicate check, essay assist, similarity, evidence insight, credits, simulation) as a BMAD spec with tight business rules and low bug risk.
- (decision) Spec covers only the first shippable slice: grounded AI drafting of DECK/STUDY_QUIZ/TEST into Class Space plus the shared AI job runtime; other ideas become future specs listed in teacher-ai-roadmap.md.
- (note) Brownfield: ClassResource kinds are DECK, STUDY_QUIZ, TEST; questions are single-choice with 2-6 options, prompt <=500 chars, TEST has correctOption; no multi-select, short-answer or essay contract exists.
- (note) Brownfield: PRD FR-21 allows Teacher AI structured drafts only with human review/publish; PRD and ARCHITECTURE-SPINE currently defer all AI generation, provider, prompt and safety work.
- (note) Brownfield: labs/infrastructure/llm.ts calls Anthropic via fetch with ANTHROPIC_API_KEY/ANTHROPIC_MODEL, 10 s timeout, JSON output and rules fallback; no queue or Redis exists; IdempotencyRecord + idempotent() helper and AuditLog exist.
- (note) Brownfield: curriculum is integrated KHTN grade 8-9 with domain strands MATTER/ENERGY/LIVING/EARTH_SKY and CurriculumOutcome codes; there is no separate Physics/Chemistry/Biology subject.
- (capability) CAP-1 owner teacher requests a grounded draft for one owned-class lesson, target kind, item count, optional outcome codes, difficulty and instruction; success: request is validated, quota-checked and recorded as one idempotent job.
- (capability) CAP-2 job runs asynchronously against an immutable input snapshot with pinned prompt and output-schema versions; success: teacher can poll status and outcome, retries never duplicate jobs or items.
- (capability) CAP-3 every generated item passes deterministic validation before a teacher sees it; success: invalid items are dropped with reason codes, valid items carry warning flags, zero valid items fails the job.
- (capability) CAP-4 duplicate detection against the class's existing questions/cards and within the batch; success: EXACT_DUPLICATE blocks unedited acceptance, NEAR_DUPLICATE only warns.
- (capability) CAP-5 teacher decides every item (accept, edit, reject) and materializes accepted items into a normal ClassResource DRAFT; success: nothing reaches students without the existing publish step and the resource is traceable to its job.
- (capability) CAP-6 bounded usage: per-teacher daily job quota, concurrency cap and token usage recorded per job; success: over-quota requests fail with AI_QUOTA_EXCEEDED and usage is reportable without billing.
- (constraint) AI never writes ClassResource content directly, never publishes, never touches attempts, scores, verdicts or progress; materialization goes through normalizeResourceContent and the existing draft/publish lifecycle.
- (constraint) No provider call inside a database transaction; job create, provider call and result persistence are separate steps.
- (constraint) TAI-01 sends no student data to the provider: input is lesson content, outcome statements and teacher instruction only.
- (decision) Runtime is DB-backed with in-process runner using lease claim (status + leaseUntil); no new queue infrastructure, works with multiple API instances.
- (decision) Job statuses are PENDING, RUNNING, SUCCEEDED, FAILED, CANCELLED; retryability is internal (attemptCount, max 2 provider attempts); failureCode distinguishes causes. Resolves earlier FAILED_RETRYABLE/FAILED_VALIDATION inconsistency.
- (decision) Raw provider response is not persisted; only validated items, dropped-item reason codes and token usage are stored.
- (decision) Prompt templates live in code with PROMPT_VERSION constants; a test pins each template digest so text changes require a version bump.
- (decision) Grounding is deterministic: server splits lesson into numbered passages; each item must cite >=1 existing passage id or is dropped as GROUNDING_REF_INVALID.
- (decision) Numeric content in stem/options flags NUMERIC_REVIEW; automatic recomputation of calculations is deferred.
- (decision) Duplicate check computed at validation time over the class's non-archived resources and the batch; normalized-text hash for exact, character-trigram Jaccard >=0.85 for near; no fingerprint table in v1.
- (decision) Per-item review lives in AI domain (AiJobItem immutable + append-only AiItemDecision); materialize requires every item decided and >=1 accepted; one materialization per job.
- (decision) Provenance is AiJob.materializedResourceId (unique); ClassResource schema and content contract are unchanged.
- (decision) Provider port with Anthropic adapter (reusing existing env) and deterministic fake adapter allowed only when APP_ENV is not production; missing provider config returns 503 AI_PROVIDER_NOT_CONFIGURED and creates no job.
- (decision) Teacher instruction <=1000 chars is passed as delimited data; output is schema-parsed; unsafe-procedure patterns drop items as SAFETY_REJECTED.
- (decision) Lesson change after generation is reported as lessonChangedSinceGeneration (snapshot digest vs current); materialize stays allowed with the flag in the response.
- (decision) Credits and payment are out of scope; token usage is logged so a later credits spec can price operations from measured data.
- (assumption) Quota defaults: 20 jobs per teacher per rolling 24 h, 2 concurrent PENDING/RUNNING jobs, max 20 questions or 30 cards per job; configurable by env.
- (assumption) Quality gate thresholds: on >=60 TEST items generated from the seeded KHTN lessons, answer-key error <=3% and >=70% accepted or accepted-after-edit by a named reviewer.
- (assumption) STUDY_QUIZ materialization drops correctOption exactly as the existing STUDY_QUIZ contract does; AI still produces it so the teacher can review correctness.
